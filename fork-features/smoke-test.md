# Smoke test

A quick manual check after rebasing the fork onto a new upstream release, once the new build is installed and Obsidian has reloaded it. One vault is enough. Each fork feature gets one step; the unit tests and specs cover the details.

1. **Right build.** Settings > Community plugins: the Tasks entry shows the new version. If it still shows the old one, restart Obsidian.
2. **Slash snippets step-aside** ([spec](slash-snippets-step-aside.md)). With Slash snippets enabled, type `- [ ] smoke /` on a new line: Slash snippets' popup shows, not Tasks'. Type a space and `due`: Tasks' popup offers a due date. Delete the line.
3. **Multi-step tasks** ([spec](multi-step-tasks.md)). On a new line type `- [ ] smoke lad` and pick `🪜 steps` from Tasks' popup, then type `one // two`. Click the checkbox: `one` is struck through and the task stays unchecked. Click it again: the task is checked with a done date. On a new line `- [ ] smoke`, run the command **Create or edit task** and click `Insert 🪜` under Actions: the description reads `smoke 🪜` and the button is greyed out. Press Esc and delete the lines.
4. **Priority menu** ([spec](priority-menu.md)). On a new line type `- [ ] smoke` and switch to Reading mode: a faint ⏺️ shows after `smoke`. Right-click it and choose `Priority: High`: the line gets ⏫. Click the ⏫ and choose `Priority: Normal`: the ⏫ is gone and ⏺️ is back. Go back to editing and delete the line.
5. **Horizon** ([spec](horizon.md)). On a new line type `- [ ] smoke hor`, pick `🔭 horizon` from Tasks' popup, then pick `this week`. On the next line type `- [ ] smoke ⏫ hor` and pick `🔭 next week`: the line reads `- [ ] smoke 🔭 next week ⏫`; delete it. Below the first line add a `tasks` block with `description includes smoke` and `group by horizon`: the task is under the heading `This week`. Right-click its `🔭 this week` and choose `Today`: the line now says `🔭 today` and the heading is `Today`. Add `hide horizon` to the block: the results no longer show `🔭 today`. Delete the line and the block.
6. **Filter clear button** ([spec](filter-clear-button.md)). In a `tasks` block's results, type `zzz` in the Filter box: no tasks are shown and a round × is at the box's right end. Click the ×: the box is empty, the tasks are back and the × is gone. Type `zzz` again and press Esc: the same.
7. **Horizon history** ([spec](horizon-history.md)). On a new line type `- [ ] smoke 🔭 today`. Below it add a `tasks` block with `description includes smoke` and `group by lateness`: the task is under the heading `On time`. Right-click its `🔭 today`: the menu ends with `Planned for <today>`, `Never pushed · tracked since <today>` and `Reset lateness`. In the Tasks settings, turn off **Horizons > Horizon placeholder**: tasks without a horizon lose their faint 🔭; turn it back on. Delete the line and the block.
8. **Nails** ([spec](nails.md)). On a new line type `- [ ] smoke nai` and pick `⚠️ add nail` from Tasks' popup: the line reads `- [ ] ⚠️ smoke`. Below it add a `tasks` block with `description includes smoke` and `group by nails`: the task is under the heading `1 nail`. Right-click the task's text in the results and choose `Add nail`: the heading is `2 nails` and the line starts with `⚠️⚠️`. Right-click the line in the editor and choose `Remove nail`: one ⚠️ is gone. Delete the line and the block.
9. **Date menu in the editor** ([spec](editor-date-menu.md)). On a new line type `- [ ] smoke 🛫 2026-01-01`. Right-click `2026-01-01`: the menu starts with `Pick a date...`; choose `Start tomorrow`: the line shows tomorrow's date. Right-click the date again, choose `Pick a date...` and click the calendar's `Today`: the line shows today's date. Press Ctrl+Z: tomorrow's date is back. Delete the line.
10. **🏁 delete for typed recurrences** ([spec](recurrence-delete-on-completion.md)). In the Tasks settings, turn on **Recurring tasks > Add 🏁 delete to typed recurrences** (note whether it was on). On a new line type `- [ ] smoke rec` and pick `🔁 recurring (repeat)` from Tasks' popup: `🏁 delete` appears after the cursor at once. Pick `every day`: the line reads `- [ ] smoke 🔁 every day 🏁 delete`. On the next line type `- [ ] smoke 2 rec`, pick `🔁 recurring (repeat)`, then press Backspace until the 🔁 is gone: `🏁 delete` goes with it. Delete the lines and set the setting back as it was.
11. **Recurrence suggestions** ([spec](recurrence-suggestions.md)). On a new line type `- [ ] smoke 🔁 every week wh`: the first suggestion in Tasks' popup is `every week when done`; pick it. Click right after `week` in the line: the popup's first item is `⏎`, not `✅ every week`. Delete the line.
12. **`block` finds depends on** ([spec](block-finds-depends-on.md)). On a new line type `- [ ] smoke block`: the first suggestion in Tasks' popup is `⛔ depends on id`; pick it: the line reads `- [ ] smoke ⛔`. Delete the line.
13. **Split tasks** ([spec](split-tasks.md)). On a new line type `- [ ] smoke 🪜 one // two 📅 2026-12-01`. Right-click the line and choose `Split task`: it becomes `- [ ] smoke: one 📅 2026-12-01` and `- [ ] smoke: two 📅 2026-12-01`. Delete the lines.
14. **Status menu in the editor** ([spec](editor-status-menu.md)). On a new line type `- [ ] smoke` and click elsewhere in the note. In Live Preview, right-click the checkbox: the menu lists `Change status to: [ ] Todo` (checked) and the other statuses; choose `Change status to: [/] In Progress`: the line reads `- [/] smoke`. Switch to Source mode, right-click the `[/]` and choose `Change status to: [x] Done`: the line gets a done date. Press Ctrl+Z: it reads `- [/] smoke` again. Switch back to Live Preview and delete the line.
15. **Complete permanently** ([spec](complete-permanently.md)). On a new line type `- [ ] smoke 🔁 every day 🏁 delete 📅 2026-12-01`. Right-click the line's text and choose `Complete permanently`: the line reads `- [x] smoke 🔁 every day 🏁 delete 📅 2026-12-01 ✅ <today>`, and no line for 2026-12-02 is added. Delete the line.
16. **Jump anchor** ([spec](jump-anchor.md)). On a new line type `- [ ] smoke ^jump-anchor`, then click at the top of the note. Press Ctrl+J: the cursor is at the end of the smoke line. Click at the top again and press Ctrl+Shift+J: a new line with an empty checkbox `- [ ]` is right under the smoke line, with the cursor on it. Delete both lines and press Ctrl+J: a notice says `No ^jump-anchor in this note`.

If a step fails, go back to the last good build before investigating.

## Adding a feature

The commit that adds a feature adds its step here: the shortest check that shows the feature is alive, one action and one thing to look at. Keep the list in the order the features were added.
